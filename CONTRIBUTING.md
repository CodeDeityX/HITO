# Contributing to HITO

Thank you for helping improve HITO.

Before opening a non-trivial pull request:

1. Describe the concrete engineering problem.
2. Explain which HITO authority, invariant, limitation, or projection is affected.
3. Add or update tests where behavior changes.
4. Preserve UNKNOWN rather than guessing.
5. Do not introduce hidden provider, network, or execution requirements.
6. Document new limitations.

A pull request should state what changed, why, what evidence supports it,
what did not change, and what remains unproven.

Unless explicitly stated otherwise, contributions intentionally submitted for
inclusion in HITO are provided under Apache License 2.0.
