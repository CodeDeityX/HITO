# HITO Roadmap

## v0.1 — Public release foundation

- clean source repository;
- reproducible dependency installation;
- CLI qualification;
- VS Code release-candidate packaging;
- final real human UI acceptance;
- canonical HITO Frog brand asset;
- public contribution workflow.

## After public release

Priorities include longitudinal continuity trials, lower onboarding and
governance-maintenance cost, clearer coverage/UNKNOWN reporting, improved
project-root UX, and qualification beyond the current Windows-first release.

HITO should not become a general-purpose code graph engine merely to increase
feature count. Dedicated structural providers may complement HITO while its
semantic/governance role remains separately defined.
