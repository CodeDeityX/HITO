# HITO Roadmap

## v0.1 — Public release foundation

- clean source repository;
- reproducible dependency installation;
- CLI qualification;
- VS Code release-candidate packaging;
- final real human UI acceptance;
- canonical HITO Frog brand asset;
- public contribution workflow.

## After public release

Priorities include longitudinal continuity trials, lower onboarding and
governance-maintenance cost, clearer coverage/UNKNOWN reporting, improved
project-root UX, and qualification beyond the current Windows-first release.

HITO should not become a general-purpose code graph engine merely to increase
feature count. Dedicated structural providers may complement HITO while its
semantic/governance role remains separately defined.

## Experimental Visual Project Explorer (Phase 3 — lab only)

An isolated Windows Visual Project Explorer experiment completed bounded R3A–R3E checks, including a 64/64 R3E prepatch regression and a native VS Code human inspection of one static `package.json` `CONFIGURES` relationship. The staged code **has not** been merged or packaged for external users. For evidence boundaries and required promotion gates, see [R3E development report](docs/EXPERIMENTAL_VISUAL_EXPLORER_R3E.md).

The next delivery milestone is source recovery from the accepted isolated stage, review of differences from the public baseline, a complete test run, clean-profile VSIX installation, and bounded real-project validation. Keep semantic authority separate from structural evidence and preserve UNKNOWN.
