# HITO Community

HITO is a local-first Semantic Continuity System in an early public release-candidate stage. Help us learn what holds up on real projects and what does not.

## How to participate

**Questions and project experiences:** GitHub Discussions, once enabled for the repository. Until then, open an issue using the existing templates, taking care not to share secrets.

**Reproducible defects:** GitHub Issues. Give the exact HITO version, operating system, input-project characteristics, steps, expected behavior, actual behavior, and a minimal safe reproduction. Never upload private repositories without authorization.

**Feature proposals and architecture:** Start with a concrete problem and constraints. Describe the authority boundary, impact on UNKNOWN preservation, and what a failing test would look like. Discuss nontrivial changes before coding.

**Pull requests:** Read [CONTRIBUTING.md](../CONTRIBUTING.md), state what changed and why, add tests for behavior changes, and preserve HITO's authority and execution boundaries.

## Areas of interest

- Structural discovery and bounded graph-provider interfaces
- Continuity across agents, machines, and sessions
- Evidence provenance and contradiction reporting
- Accessible VS Code UX and first-run onboarding
- Linux and macOS qualification
- Real-world falsification and transparent benchmarks
- Documentation, diagrams, and translations

## Community commitments

We welcome criticism of the design, including evidence that HITO adds no value in a particular workflow. Do not promise outcomes, undisclosed paid bounties, or privileged access. Use [CODE_OF_CONDUCT.md](../CODE_OF_CONDUCT.md) and [SECURITY.md](../SECURITY.md) for appropriate conduct and security disclosures.
