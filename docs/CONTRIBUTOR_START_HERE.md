# Your first contribution to HITO

You do not need to understand all eleven movements or all internal modules to contribute.

1. Read the README and [limitations](LIMITATIONS.md).
2. Try HITO against a **disposable project** using [Quick Start](QUICKSTART.md).
3. Find one observable gap. State what was known, what HITO displayed, and whether authority was overstated or lost.
4. Open an issue with a minimal reproduction, or propose a bounded improvement.
5. If code changes, add an evidence-bearing regression and document unchanged invariants.

### Good first contributions

- Fix a confusing README example.
- Reproduce a Windows/VS Code installation edge case.
- Improve the formatting of UNKNOWN / PARTIAL in UI.
- Add a documented fixture with no private content.
- Test the quick start on a clean environment and report friction.

We prefer one small, verifiable improvement over a broad feature without acceptance criteria.
