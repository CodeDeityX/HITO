# HITO v0.1.0-rc.1 — first public release candidate

**Semantic continuity for software projects.**

HITO is a local-first system for preserving bounded project meaning, evidence, uncertainty, continuity, and the difference between a suggested step and a justified step across CLI, VS Code, and agent-facing projections.

## Included in this release

- HITO CLI commands for bounded project observation, initialization, intake, status, next, why, and MRI.
- VS Code surfaces for Guided Project, Engineer Detail, Forensic Detail, and Agent Context.
- Preservation of `UNKNOWN`, `PARTIAL`, and `INDETERMINATE` where the evidence does not justify certainty.
- Canonical shared semantic result identity between the CLI, VS Code, and agent-facing contexts in the qualified test subject.
- Read-only guidance with execution authority disabled in the accepted projection.
- The official HITO Frog mascot.

## Qualification scope

The frozen RC was qualified primarily on Windows using controlled, bounded fixtures. A fresh-install VS Code acceptance passed. The parity test confirmed a PARTIAL semantic observation, qualified positive facts, and preservation of unknown current/next claims rather than invented recommendations.

## Limitations

This RC **does not** claim exhaustive structure mapping, full behavioral comprehension, or automatic safe mutation for arbitrary projects. Structural acquisition is bounded. Mac and Linux qualification and broader third-party project testing remain opportunities for contributors.

## Install from source

See [Quick Start](../../docs/QUICKSTART.md). Build the VSIX with `npm ci --ignore-scripts` and `npm run package:vsix`, then use **Install from VSIX** inside VS Code. Initialize only projects you control; first try a disposable fixture.

## Contribute

Reproducible reports are welcome: missing structural facts, continuity breakdowns, evidence not reflected in the UI, incorrect certainty, inaccessible onboarding, and cross-platform installation findings.
