# Proposed starter issues — review before publishing

These are community backlog drafts, **not published GitHub issues**. Confirm each gap is still relevant before opening it.

1. **[good first issue] Clean VS Code first-run walkthrough.** Create and independently reproduce a Windows clean-install walkthrough against a disposable repository. Acceptance: clear screenshots without private paths, no execution of subject application code.
2. **[docs] Explain UNKNOWN / PARTIAL / INDETERMINATE.** Acceptance: one evidence-bearing example of established facts coexisting with unresolved next/current/health; no invented guarantees.
3. **[research] Structural acquisition gap fixture.** Acceptance: synthetic repository, expected nodes/edges, observed gaps, bounded result, independent repro steps.
4. **[rfc] Pluggable graph/AST structural provider.** Acceptance: proposed interface, provenance, partial/stale state, trust boundary, no semantic-authority elevation.
5. **[help wanted] Linux/macOS qualification matrix.** Acceptance: explicit OS/runtime combinations and scoped checks, no PASS without evidence.
6. **[community] Continuity falsification across sessions.** Acceptance: frozen project identity, evidence trace, reproducible negative/positive outcomes, no reinitialization to force success.

Labels to consider: `good first issue`, `help wanted`, `bug`, `enhancement`, `area:vscode`, `area:cli`, `area:acquisition`, `area:docs`, `research`, `rfc`, `platform`, `onboarding`.
